# Supplier intake integrity – PR #824

Verified 2026-10-16. Tracks #823; does not close the complete AI bookkeeping roadmap.

## Implemented scope

- Supplier invoice references are unique per company AND registered supplier, rather than across all suppliers of a company. A generated NFKC/uppercase/whitespace-normalized comparison key preserves the original reference. Punctuation and leading zeros remain significant. Original PDF hashes also have a company-scoped unique index.
- Supplier identities with a populated organization number receive conservative normalized duplicate protection, scoped to company and country. Legacy unknown-country identities cannot silently be duplicated with an asserted country. This is not registry verification and does not prove the authenticity of an invoice.
- Supplier create/profile/payment edits use exact revisions and stable request identities. Database triggers write the associated change history in the same transaction. Audit failure rolls back the supplier mutation. Clients cannot forge/rewrite history or delete suppliers and cascade away history.
- Invoice input and passive PDF structure are validated before supplier creation. Hosted intake uploads the original first and uses deterministic invoice/document identifiers and exact read-back checks to recover already committed steps after network failures. Context checks bind the operation to the original company, user and role. Storage is not a SQL transaction; partial steps can remain for explicit retry and the UI says so.
- A manual `Läs uppgifter från PDF` action prepares empty fields from the existing local text reader. A previously unknown supplier name can prepare the new-supplier form; a unique exact normalized name can propose an existing supplier. Neither is verified legal identity. The user still checks and submits the form. This is rule-based local text extraction, not a model call. Organization numbers and bankgiro are not fabricated or automatically extracted by this feature.
- No automatic saving on PDF read, attestation, posting, payment, model release or external processing of customer documents is enabled. Existing financial RPCs remain the only intended posting path.
